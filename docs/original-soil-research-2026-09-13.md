## 2. 为什么看起来真实、计算又快

本地XML把地面与两层斗中土分别存为320×320高度场，覆盖16×16米，插件按约5厘米水平网格计算；地面材质使用floor_texture.png。它没有为画面上每个细小纹理点建立独立三维颗粒。外观包含连续表面和纹理细节，因此不能以截图颗粒感推断物理自由度。

上游初始化采用多频Simplex噪声；Step先检查工具位移，再更新工具和随工具携带的土、处理相交格子，最后迭代到平衡或次数上限。[初始化与Step源码](https://raw.githubusercontent.com/KennyVilella/soil_dynamics_cpp/main/soil_simulator/soil_dynamics.cpp)

松弛算法比较邻接土柱坡度与休止角，将过陡处向相邻格转移，检查范围受impact_area约束。这类规则能形成可理解的挖坑、堆积和坡面变化；它省略了完整三维应力演化。[松弛源码](https://raw.githubusercontent.com/KennyVilella/soil_dynamics_cpp/main/soil_simulator/relax.cpp)

**速度边界：** 上游“更新小于1ms”是设计目标，不是本项目测得的端到端性能。本地XML的水平和竖向单元均为5厘米；Step以铲斗任一角点相对上次土壤更新的最大位移判断，小于最小单元一半即2.5厘米时返回。超过10厘米只给出有效性警告但仍更新。该距离门控会使慢速接触和初始入土以离散跳变响应，不能原样搬进MPM近场。soil.cc的Compute在发生更新后仍遍历并复制三张完整320×320高度场，源码注明应改成局部更新；不能说原版每一层都已经增量优化。

**守恒检查边界：** soil_dynamics_cpp提供按离散土柱数核对地形与斗中土总体积的CheckVolume，并检查斗中土位置表与高度层的一致性；示例可逐步调用。截图对应的生产插件Compute没有调用该检查，因此原窗口运行不能自动获得“逐步守恒已审计”资格。即使通过，它也只证明CA离散土柱数量守恒，不证明三维应力、土反力、密度标定或装载稳定性正确；首轮无窗口代理基准将显式启用并记录该检查。

**物理边界：** 作者把土壤库定位为快速一阶位移模型；多运动物体、力计算和异质土属性仍列在待办中，挖掘机仓库也列出土壤反力待实现。这支持将其用作简化参考，不能把视觉可信度当作力学标定。[土壤库](https://github.com/KennyVilella/soil_dynamics_cpp)、[挖掘机仓库](https://github.com/KennyVilella/excavator_simulator_mujoco)

## 3. 当前值得吸收什么

| 可借鉴项 | 当前项目怎么使用 | 优先级、成本与验收 |
|---|---|---|
| 高度图与紧凑地形描述 | 复用已有双视角地形，提取表面坡度、可见边沿、候选条带和未知区域；用于选点，物理仍用MPM | P0，低到中；已具备地图，不重建感知。验收每铲后地图反映新坑，未知不填实，能生成多个可达候选 |
| 简化工具几何用于快速预筛 | 用斗尖/斗口和扫掠包络估计候选挖取范围，然后以真实CAD检查全路径 | P0，中；已有几何基础但抬斗逆解未通过。验收切入、抬升、运输、退出都可行；简化体不能代替最终碰撞检查 |
| 局部更新与不同频率调度 | 先测感知、候选搜索、显示、数据拷贝占比；有瓶颈再缓存未变部分，保留时间戳、失效和定期全量核对 | P1，中；不能把工具不动当土体不动，不能冻结远处MPM粒子。验收与完整重算结果一致并测端到端延迟 |
| 连续表面＋土色纹理 | 优先复用已有soil_surface.py及粒子切换；只在演示可读性确有问题时改善 | P2，低到中；现有连续显示已实现，避免重复建设；不能隐藏飞点、填实空隙后拿显示体积计分 |
| 地形/斗中土分区与守恒自检 | 借鉴分区清楚、转移可追溯的组织思想；复用当前固定粒子质量账本 | 保留已有能力，核心冻结；新接线只读使用既有字段，不新增回收流程或更换体积账本 |
| CA或几何模型快速预演 | 当前启动独立无窗口CA核心，用相同地形和挖法预演6～12组首轮选点候选 | P0，中；先验收速度、守恒和可比较性，再用少量MPM核对排序、前列保留、挖后地形与失败漏检，不能只证明快 |
| 快速RL训练环境 | 代理可用于选点和轨迹参数策略预训练；受力残差只在MPM或独立标定的受力代理中训练 | P1，高；上游无反力，不能用CA训练低层受力适应或与当前MPM重复叠力 |

P0为当前选点代理与连续闭环必要工作；P1为铲土学习及效率改进；P2为条件后续项。成本为工程复杂度判断，不是实测工期。当前不安排独立“美化土壤”或“重造快速土壤引擎”项目。

## 4. 不直接移植的部分及原因

- 休止角滑落不等于当前黏聚台阶的破坏规律。将整堆强行整理为休止坡会改变用户要保留的工作面，不能用它再次全局削弱正常MPM。
- 高度场只提供受限的竖直层表达；当前深切、斗中堆高、倒扣、土块与车厢接触需要真实几何/三维验证。原插件的硬编码斗形也不能直接替代我们的CAD。
- 当前MPM已经产生原生接触反力，不能额外再叠一套CA/FEE阻力当“增强真实”。历史等效力模型和上游原生能力应分开。
- 暂不混合“远处CA、近处MPM”。粒子激活、界面体积/质量、动量、应力历史和反复切换都需要专项验证，不是简单调参。
- 原版外观自然并不能解释当前局部细串或斗底聚点的根因；正常MPM已在原手操及保持试验中通过主体稳定检查，只有影响当前闭环的缺陷才进入定向修复。

## 5. 用户本日范围更新

不开发掉落在地上的土的识别、导航、回铲或二次装车策略，也不为这一假设需求扩展账本、奖励和测试矩阵。只有用户重新提出明确需求才启用。

掉落物继续自然存在，既有库存照常记录；不删除、不补回、不瞬移、不算作已装车。运输掉落对最终有效装载的影响仍保留，地面散土如妨碍路径仍由普通几何检查处理。后续下铲目标来自主要土堆更新后的工作面，不专门搜集散落土；若正常挖取偶然带起某粒子，不新增特殊分支或改写账本。

当前下一步是原版CA无窗口基准、6～12组下铲候选预演及少量MPM排序复核；通过后进入连续多铲，再做纯铲土参数策略与受限残差学习。当前总体优先级统一见[总体规划](PROJECT_PLAN.md)；本段其余内容是2026-09-13历史研究记录。
