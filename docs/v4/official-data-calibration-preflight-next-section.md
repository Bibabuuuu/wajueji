# 队友GPT下一任务：官方可见数据标定前检查

更新：2026-09-20。状态：`已授权实施`。本工作包只建立官方可见数据到程序化场景参数的离线契约，不修改R2高度场、刚体桥或物理。

## 背景与目标

当前石块场景只在方向上参考官方画面的碎石/大块石构成，数值仍以铲斗几何和工程可铲运约束为主：实际内侧净宽`0.599490m`已测量；普通场景80%石块不超过`0.16m`、每场20块、四种原型各25%、合成起伏面和聚集参数均是`synthetic_baseline`；密度`2600kg/m³`是仿真假设。

本任务建立一个可人工录入、可审计的官方可见材料摘要，让后续官方数据能够校准可见粒径、形状、覆盖率和空间分布，同时明确不能从画面推断的力学量。

## 允许新增

- `configs/v4/official-visible-material-summary-template-v1.json`
- `src/v4/build_official_scene_calibration_preflight.py`

- `reports/v4/official-scene-calibration-preflight-2026-09-20-v1/`
- 在本文末尾回填实施状态

其余文件只读。不得修改`scene-reconstruction-v1.json`、R0/R1/R2配置、桥、MJCF或现有报告。

## 实施内容

1. 定义人工审核后的官方可见摘要schema，字段至少包括：来源ID/帧范围、画面内铲斗参考宽度、石块/铲斗相对等效粒径分位数、可见石块计数或密度、表面覆盖率、长宽比、棱角度类别比例、最近邻/聚集代理、可见表面坡度与起伏尺度，以及每项的不确定度和来源状态。
2. 允许绝对尺度未知。此时保留无量纲`d/D_bucket`；只有存在可靠尺度时才换算米制。任何换算必须记录统一场景缩放系数，不得逐颗缩小难例。
3. 输出当前基线差距报告：明确哪些字段已经来自实测铲斗几何，哪些仍是合成基线或密度假设，哪些官方摘要尚为空缺。
4. 输出候选覆盖建议，但不得直接改写场景配置。建议应给出普通/稀疏大石/卡滞三类需要调整的粒径桶、数量或覆盖率区间，并保持`maximum_capacity=20`、首轮6个20石场景和13石边界延期不变。
5. 明确拒绝从图像/点云直接推断：地下石块、单块密度、摩擦、恢复系数、破碎强度、液压能力和斗—石接触参数。
6. 空模板也必须生成有效报告，状态为`official_visible_measurements_pending`，不得伪造官方统计。

## 验收

- schema拒绝缺来源、非有限值、分位数乱序、比例不闭合、负不确定度、单位混用和逐颗缩放指令。
- 相同摘要重复生成逐字节一致；输入任一测量或来源哈希变化，输出绑定随之变化。
- 当前基线中的`synthetic_baseline`、`r0_frozen_assets`、`r0_density_assumption`逐项列清，不把后两者误写成官方真值。
- 输出明确区分`observed`、`human_reviewed_estimate`、`synthetic_assumption`和`unknown`。
- 专项测试通过，`git diff --check`通过。

## 明确不做

- 不下载、抓取或猜测平台内不可访问数据。
- 不运行MuJoCo/Newton/Warp，不修改高度场，不训练。
- 不把官方可见统计写成地下分布或真实材料力学标定。
- 不增加新的场景数量；本任务只改变未来参数来源和校准区间。

## 交接

完成后主线将把人工确认的摘要作为`scene-reconstruction-v1`后续版本的输入来源，并比较“当前合成基线”和“官方约束候选”的差异。没有人工审核数据时，只交付schema、空模板和差距报告，不生成伪校准配置。
