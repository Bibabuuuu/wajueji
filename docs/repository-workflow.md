# GitHub 与两台电脑的协作方式

更新：2026-09-14。

GitHub 仓库：`https://github.com/Bibabuuuu/wajueji.git`。笔记本可以访问 GitHub，因此由笔记本承担 `commit/push/pull`；GPU 台式机没有 VPN，当前只承担仿真运行。台式机不需要为了本轮长任务立刻连接 GitHub。

## 当前原则

- 开发源码和文档先在笔记本 Git 工作树中提交，再由笔记本推送。
- 台式机每个正在运行的候选目录都视为冻结输入；长任务结束前不覆盖、不拉取、不切换其中的源码。
- 需要把新提交送到台式机时，笔记本先从 Git 提交导出或检出到新目录，再通过 Tailscale/SSH 复制。台式机始终用新的运行目录和运行名，避免污染已有证据。
- 粒子快照、逐步日志、压缩归档和视频不进普通 Git。它们按运行名保存在证据目录，并以摘要、哈希或小型报告进入仓库。
- 两位队友先只读仓库和交接文档；具体模块、写权限和分支分工须经团队讨论后再确定。

## 推荐的日常步骤

1. 开始前运行 `git status`，确认自己所在分支和未提交改动。
2. 每项改动使用独立的 `codex/...` 或约定的队员分支。
3. 提交中只包含本项源码、文档与小型证据；先检查是否误加入日志、快照、凭据和本机连接信息。
4. 笔记本推送分支到 GitHub，通过提交或拉取请求交流；不要用文件名后缀复制“最终版2”“最新版3”。
5. 需要上 GPU 验证时，从明确提交导出到台式机的新目录，记录提交号、运行名和输入哈希。
6. 验证结束后只回收报告、选定截图和哈希；原始大文件继续留在台式机。

## 首次接入

仓库当前在 GitHub 页面上显示为公开仓库。参赛提交前应先在 GitHub `Settings → General → Danger Zone → Change repository visibility` 中改为 **Private**，再进行首次源码推送。之后在 `Settings → Collaborators` 邀请两位队友；队友接受邀请后即可克隆和创建自己的分支。

如果台式机以后需要直接使用 Git，而其网络仍不能访问 GitHub，可以继续让笔记本充当同步端，不必给台式机配置 VPN。Git bundle、本地裸仓库或 Tailscale 文件传输都能保留提交号；本项目先采用“笔记本检出明确提交后复制到台式机新目录”的简单方式。
