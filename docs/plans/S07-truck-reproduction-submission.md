## 车斗物理边界

- 车体CAD外观不等于物理承载已经验证。
- MPM—车接触由Newton处理；刚石—车接触由MuJoCo静态车体几何处理；同一接触不能在两个后端重复求解。
- `TruckReceiver`只做独立稳定接收和几何/库存审计，不能替代物理车斗碰撞。
- 47石预接触门保留了车体视觉和receiver合同，但没有授予车斗MPM承载资格。
- 稳定车内净增体积必须使用互斥库存和保持窗计算，不能只看画面或瞬时穿过接收区域。

## 完整单铲链

`合格带载脱土 → 安全举升/回转 → 对准车斗 → 卸料 → 稳定接收 → 退出 → 返回`

## 同实例三铲

- 只创建一个混合物理实例。
- 每铲都有规划观测、dispatch复核、选点、APPROACH、接触、卸料和返回记录。
- 第2/3铲状态摘要、物理步和观测必须晚于上一铲结束。
- 三铲之间只重置高层局部计时或目标，不重置MPM、石块、机构实际状态、车内库存或物理时间。
- 任一铲失败时整轮不记通过；失败原样保留并从完整初态重跑。

## 冻结与独立复现

- 冻结Git提交或源码清单、配置、场景、检查点、运行包和依赖SHA。
- 开发序列与独立复现使用不同运行ID和输出目录。
- 独立复现从完整初态开始，不复用开发末态。
- 报告包含环境、输入、每铲时间线、状态摘要、评价量、检查、失败边界和退出码。
