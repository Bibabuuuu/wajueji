# R2六场景模型只加载报告

本目录保存R2前两道实现门：把6个普通/稀疏的20石场景装配为独立MJCF并逐一执行`mj_loadXML`结构检查；随后从冻结R1桥确定性派生一个R2桥源码，在不修改R1文件的情况下逐场启动、初始化控制器并输出时间0状态。

结果为`r2_six_scene_load_only_passed`：6个场景全部具有20块真实石块，合计检查120条石块记录；每个模型均为`nq=159`、`nv=138`、`nu=12`、`nplugin=0`，含18个开口铲斗代理，石块名称和自由关节地址连续。没有占位石块，没有运行时增删石块，冻结源模型哈希保持不变。

容量口径只有一个：未来R2桥最大容量为20，同一实现读取当前已加载模型的实际固定石块数，模型运行期间不得改变数量。这里首轮只装配了6个20石成功候选；3个13石卡滞场景继续保留为延期边界诊断，不需要第二套桥，也不补7块假石头。

第一道门现在还核对每个场景由已审核`scene-manifest.json`确定性生成的`65×65`浮点高度场。高度场对原解析斜坡/双高斯曲面的最大插值误差为`0.098145mm`，低于`0.15mm`门槛；源清单、资产、模型均有哈希绑定。原`ground_plane`继续服务机构原碰撞位但不与石块碰撞，新`r2_surface_terrain`只支撑石块。纯加载检查没有调用`mj_forward`或`mj_step`，也没有修改桥；其根结论读取`report.json`。

第二道门结果为`r2_six_scene_bridge_init_passed`：同一个生成桥读取加载模型维数和连续命名自由关节，六场均返回20条真实石块状态、最大容量20、运行时增删禁用、占位石禁用。初始化调用`mj_forward`配置控制器和时间0运动学，但没有调用`mj_step`，六场时间均保持0。根结论读取`bridge-init-report.json`，生成源码及其清单位于`generated-bridge-r2.cc`和`generated-bridge-r2-manifest.json`。

第三道数值烟测用同一桥对六场分别执行1秒零命令沉降，共14400个内部子步。120个石块身份全部保留、六场均观察到地面接触、禁止接触0、最大闭链`0.185600mm`；高度场接触均归为地面，坡道计数为0。根结论读取`settling-report.json`。

高度场关闭了“落到错误平地”的缺口，但烟测又暴露初态稳定性问题：清单生成器只保证随机朝向的石块离解析表面`6mm`、边界合格且互不穿插，没有保证该朝向能静态支撑。六场最大总位移仍为`0.1337–0.2065m`，最大水平位移`0.0977–0.1762m`、最大向下位移`0.0838–0.1219m`；`sparse-large-rock-seed-26091921`末态最大平动速度为`0.00796m/s`。因此`r2_six_scene_settling_smoke_passed`只表示桥、数值、高度场装配和接触分类没有立即失效，不是目标重建场景沉降通过。生成并复核稳定初态之前，不进入受控进斗、携带或满斗率验收。
