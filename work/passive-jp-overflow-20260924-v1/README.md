# 零硬化配置的 Jp 历史溢出修复

用户授权在继续采集期间隔离修复。新第一铲采集进程运行时仅做CPU检查、未改绑定源码；待1132帧正常结束后才使用GPU复验、接入新逻辑。新第一铲独立审查见 [记录](../new-chain-first-review-20260924-v1/README.md)。

## 原因与范围

第三铲卸料第2297帧单个float32 Jp溢出；此前最大值在2296帧达到1.588e38。当前固定配置hardening=0，Newton的hardening_law直接返回1，Jp不参与屈服强度，但原更新仍按塑性增量累乘。该故障是未参与本配置力学的历史标量超出数值范围，不等于已经证明出现真实土体失稳。

新策略`zero_hardening_frozen_jp_v1`仅允许所有硬化系数**精确为0**且输入Jp有限、严格为正。每次更新暂以中性值计算未使用的标量分支，返回时恢复原输入Jp；弹性、应力、粒子运动、接触和保护不修改。初始值不清零、不改写原文件；该策略不再记录后续累积塑性Jp，因此禁止据其历史切换到非零硬化模型。非零/混合硬化、非有限或非正输入一律拒绝，不用修复逻辑掩盖坏输入。

默认旧检查点不悄悄启用。`audit_layered_47_cycle.py --freeze-passive-jp`显式启用，保存策略及实现SHA；后续runtime与手操恢复从元数据继承。新`prepare_47_next_scoop_local.sh`在源保持阶段显式启用。原始第一铲旧入口暂保持原行为，后续接触记录必须保留策略/源码版本，不把新旧Jp当作同一历史标签。

- 同源同指令候选24帧与新基线的23个其他状态数组逐值一致；Jp按新策略保留。
- 候选重放原后续813帧，越过原2297帧故障，再追加180帧零命令：993帧全部硬门、材料/防漏守卫通过；Jp全数组精确等于源值，所有数值数组有限。仅这段故障窗通过，不冒充完整卸料返回通过。
