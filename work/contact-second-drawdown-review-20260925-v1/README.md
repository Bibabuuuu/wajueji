# 第二铲343帧回落调查：参考端点饱和与执行速度失配

只读CPU分析，无新物理、无改控制。输入为v2补收343帧的动作、物理、native半步和响应矩阵记录；哈希在report.json。

已验证时序：底层铲斗目标在267帧达到0.852m并将目标速度归零；实际缸位仍约0.848m。上层CarryFeedback以实际缸位距0.852m的剩余量继续请求约5mm/s收斗，其运动学预览直接用请求缸速推进，而没有使用底层已经饱和为0的参考速度。斗杆继续执行依赖正收斗速度的配合运动。

中心270帧达最高点，343帧相对峰值下降10.4319mm，历时1.21667s，最大单帧下降1.21084mm；斗原点245帧达峰、末态下降20.4800mm。整体过程仍比补收入口中心高174.065mm、原点高82.614mm。不是整个过程一直下压，也不是10mm单帧跳落。

末帧：上层收斗+4.9076mm/s，native目标速度0，实际该帧平均缸速-4.4436mm/s；斗杆请求+4.3799mm/s、实际+6.8268mm/s；动臂请求0、实际-1.0950mm/s。上层运动学预计中心+28.198mm/s，使用native目标速度预测-14.884mm/s，实际中心-72.650mm/s。以实际四缸增量作闭链切线分解，中心速度中动臂/斗杆/收斗约-10.24/-23.20/-39.01mm/s，合计与实际相符。上层全343帧期望竖直速度始终+0.08m/s，阶段始终FINISH_CURL，无阶段切换，无投影改写，原物理hard_guard全通过。

底层参考控制器明确以自己的reference.target/reference.velocity执行限幅，真实q/qd在MuJoCo伺服反馈中；这是正常端点保护，不应删除。带载实际缸位滞后于参考，在267之后收斗明显减速，后段轻微反向。土的作用和负载变化存在，但日志不足以完整隔离刚性石—斗接触冲量，不能宣称无接触作用或全部由单一因素造成。未证明旧第一铲截图振荡与此完全同因。

最小修复建议（尚未实现）：补收配合计算和预览考虑native参考位置/速度以及端点剩余量；临近饱和或实际≥99%时平顺转为保斗抬升，不再依赖继续卷斗来抵消斗杆造成的下移。仍保留原变化率、端点、收斗及碰撞保护，10mm累计门只限FINISH_CURL。不通过加大回落阈值或增加收斗上限绕过；先用当前保存状态离线检查，再决定有界物理。
